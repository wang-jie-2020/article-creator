# 五个概念，看懂 Vibe Coding 是怎么运转的

你大概已经见过这类画面了——有人在编辑器里打一段中文，AI 自动生成了整套代码，然后一个按钮，网站就上线了。

这不是魔术。它的背后是一套被越来越多人称为 **Vibe Coding** 的工作方式：你不用写代码，你只需要描述你想要什么，AI 替你完成剩下的一切。

但问题是：如果你只用最基础的方式跟 AI 对话——每次打开聊天窗口、每次重新解释自己的项目、每次手动复制粘贴——你很快就会撞到天花板。要么上下文太长 AI 开始"忘记"你的要求，要么你发现很多重复劳动完全可以被自动化。

Vibe Coding 真正高效的人，都在用五个核心概念搭建自己的"AI 工作台"。这五个概念分别是：**Subagent**、**Hooks**、**MCP**、**Skill** 和 **Claude.md**。

这篇文章不会教你写一行代码。我会用最直白的比喻，让你理解它们各自是干什么的，以及它们如何拼在一起，变成一套完整的 AI 协作系统。

---

## 先认识这五个概念

### 1. Subagent（子代理）—— 把活外包给"小助手"

**一句话解释：你让 AI 帮你干活，AI 再派自己的"小弟"去并行处理，然后把结果汇总给你。**

想象你是一个主编。你拿到一个选题，不是从头写到尾——你把"查资料"派给实习生 A，"整理数据"派给实习生 B，"找案例"派给实习生 C。每个人只干一件事，干完之后向你汇报。你最后汇总、审核、成稿。

Subagent 就是这个逻辑。

当你给 AI 下一个复杂任务时（比如"帮我检查整个项目的安全性"），AI 不会一个人闷头干。它会在后台 spawn（生成）多个子代理——一个查 SQL 注入、一个查权限配置、一个扫描密钥泄露——它们同时跑，各自完成后把结果返回给主代理，主代理再合成一个完整的报告给你。

**为什么它重要？** 因为单个 AI 的"注意力"是有限的。一次聊太久，它会"忘掉"你最早说过的话（上下文窗口限制）。Subagent 让你把大任务拆碎，每个小任务在一个干净的上下文里跑，既不互相干扰，又可以并行加速。

**类比扩展：** 就像是给 AI 配了一个"分身术"。你只跟本体说话，但本体可以随时分出一批分身去办不同的事，办完自动回收。

---

### 2. Hooks（钩子）—— 自动化触发器

**一句话解释：当某个事件发生时，自动触发一个动作。就像你出门前，"门一关"这个动作自动触发"检查钥匙带没带"这个念头。**

Hooks 最早来自编程概念——"钩子"让你在系统运行的关键节点，插入自己的逻辑。在 Vibe Coding 里，hooks 可以理解为：**在 AI 执行流程的特定时刻，自动执行的脚本或规则。**

举个例子：

- **Prompt Submit Hook**：你在每次给 AI 发消息之前，hook 自动在后台检查你有没有不小心粘贴了 API 密钥，如果有就拦截。
- **Post Tool Use Hook**：AI 每次编辑完一个文件，hook 自动运行代码格式化工具，确保代码风格一致。
- **Session Start Hook**：每次你打开项目，hook 自动加载项目的核心文件摘要，减少你"重新介绍背景"的时间。
- **Stop Hook**：每次 AI 完成一轮回复后，hook 自动对改动做一次安全检查。

**类比扩展：** Hooks 就像办公室里的自动化流程。比如"每次合同入系统，财务部自动收到审批提醒"——你不需要每次手动通知财务，流程自己就跑完了。

在 Vibe Coding 里，hooks 是你建立"自动化纪律"的关键。你设置一次规则，它就会在你每次工作时自动执行，不需要你反复提醒 AI。

---

### 3. MCP（模型上下文协议）—— AI 的"万能转接头"

**一句话解释：就像 USB-C 让笔记本能同时接显示器、充电器、硬盘、鼠标——MCP 让 AI 能同时连接各种外部工具和服务，用一个标准接口。**

MCP 的全称是 Model Context Protocol（模型上下文协议），由 Anthropic 提出，正在被越来越多的工具采纳。

**没有 MCP 之前：** 如果你想让 AI 帮你查数据库、发 Slack 消息、看 GitHub 上的代码、搜索公司的内部文档——你需要为每一个"AI 到外部工具"的连接写一套定制代码。而且每个 AI 产品的连接方式都不一样。就像你每次去一个新国家要带不同的转换插头。

**有了 MCP 之后：** MCP 定义了一个标准协议。任何遵从这个协议的工具（不管是数据库、API、文件系统、搜索引擎），都可以像 USB 设备一样"即插即用"地被 AI 调用。AI 不需要知道每个工具的"内部结构"——它只需要通过 MCP 这个标准接口说"给我这个数据"，MCP Server 负责实际去执行。

**类比扩展：** 把 AI 想象成一个盲人 CEO。他坐在办公室里，不能直接操作电脑、查系统、发消息。但他有一个对讲机（MCP），通过这个对讲机他可以命令不同部门的人（MCP Server）替他干活——"帮我查一下上个月销售数据"、"在 GitHub 上创建一个 issue"。MCP 就是那个对讲机的频道标准——所有部门都监听同一个频道，都听懂同一个指令格式。

**为什么它对 Vibe Coding 重要？** 因为 Vibe Coding 的核心是"用自然语言驱动一切"。MCP 让"驱动一切"这件事真正在技术上变得可能——你不用为每个外部工具学习一套新对接方式，AI 已经通过 MCP 打通了所有接口。

---

### 4. Skill（技能）—— 可复用的专业"剧本"

**一句话解释：Skill 就像一套预制菜的操作说明书——你不需要每次做一道新菜时重新发明菜谱。加载一个 skill，AI 自动获得完成特定任务的完整方法论。**

每个 skill 本质上是一组"提示词 + 规则 + 参考材料"的打包。当你调用一个 skill 时，AI 的上下文中会注入这套完整的方法论——该怎么做、有什么注意事项、输出格式是什么——然后 AI 按这个"剧本"执行。

举个具体例子，看看这个"文章写作 skill"里包含了什么：

- 什么情况下应该启用（"写博客文章、指南、新闻简报"）
- 写作流程（先搭大纲→写草稿→删模板套话→交付）
- 禁用什么模式（不能用"在当今这个快速变化的时代"这种 AI 模板句）
- 质量检查标准（每段是否增加了新信息？文体是否一致？）

你只需要说一句话——**"帮我写一篇关于 MCP 的科普文章"**——skill 就加载了所有这些专业知识，AI 不再是一个"泛泛的写手"，而是一个知道你喜欢什么风格、有什么规则、什么该做什么不该做的"定制写手"。

**类比扩展：** 想象你是一个导演。你的团队里有一个摄像师。如果每次拍摄前你都要从头教他——"光圈怎么调、构图怎么摆、色调怎么定"——你会疯掉。Skill 就是你给摄像师的一份"拍摄手册"。你喊一句"拍街头风格"，他就自动按手册调好参数开始工作。

**任何 task 都可以做成 skill：** 写代码、写文章、画图表、做 PPT、审查代码安全、翻译文档——只要是一个需要反复执行且有固定方法论的任务，都可以封装成一个 skill。

---

### 5. Claude.md —— AI 的"使用说明书"

**一句话解释：这是一个存于项目根目录或用户目录的文本文件，告诉 AI："关于这个项目和我这个人，你想知道的一切都在这里。"**

Claude Code（以及类似的工具）会在每次对话开始时，自动读取项目中的 `CLAUDE.md` 文件，甚至用户主目录下的全局 `CLAUDE.md`。这个文件定义了：

- **你是谁**：你的代码风格偏好、你的沟通风格、你的技能水平
- **规则**：哪些能做、哪些不能做（比如不能提交密钥、不能乱装依赖）
- **项目背景**：这个项目是干嘛的、关键文件在哪、架构是什么样的
- **提效默认策略**：比如"默认不要扫全盘，先定向检索"、"别主动跑 git status"

**Claude.md 真正的价值不在于"告诉 AI 怎么干活"——而在于消除每一次对话的"冷启动"成本。**

没有 Claude.md：你每次打开 AI 助手，都要先花 5-10 分钟"介绍自己"和"介绍项目"。AI 对你和你的项目一无所知，像一个第一天入职的新同事。

有 Claude.md：AI 在对话开始前就被"预加载"了关于你的一切。它不会提不合适的建议，不会犯你明确禁止过的错，不会用你不喜欢的语气跟你说话。它不是"每次重新教你一遍"——它是"你已经写好的说明书，AI 每次自动读一遍"。

**类比扩展：** 你开了一家餐厅。Claude.md 不是你每天给厨师的"今天做什么菜"的菜单——它是贴在厨房墙上的"食品安全条例"和"出品标准"。不用每天重读，但它永远在那里生效。

## 这五个东西是怎么拼在一起的

单独看，每个概念都很好理解。但真正有意思的是**它们之间的配合**。用一个完整的场景来展示：

### 场景：你要做一个个人博客网站，从零到上线

**第一步：Claude.md 先定义游戏规则**

你打开项目。AI 自动读取了 `CLAUDE.md`。它知道了：

- 你是一个设计师，不是程序员（AI 要解释概念时会更通俗）
- 你偏好简洁的设计风格，不要动画花里胡哨
- 不要擅自改你的设计文件，只给你建议
- 代码风格用 Tailwind CSS + React

你不需要再告诉 AI 这些。它已经知道了。

**第二步：Skill 加载专业能力**

你输入："/frontend-design 帮我搭建博客首页"

这个 `/frontend-design` 就是调用了一个 skill。AI 现在被注入了一整套"前端设计方法论"——它知道怎么排版、怎么配色、怎么组织页面结构、避免哪些设计陷阱。

你不需要详细描述"请帮我画一个响应式网站，中间有一个两栏布局，左边是文章列表，右边是侧边栏"。Skill 已经把专业能力装载好了，你可以直接用"设计直觉"级别的语言跟它沟通。

**第三步：MCP 连接外部工具**

AI 在写代码的过程中，需要访问你放在 GitHub 上的旧博客数据来迁移内容。通过 MCP，它直接调用了 GitHub MCP Server——读取你旧仓库的文件、提取文章内容、按新格式重新组织。

如果没有 MCP，你需要手动去 GitHub 下载文件，再粘贴给 AI。有 MCP，AI 自己就完成了这个"跨系统取数据"的步骤。

同样地，当博客写好要发布时，AI 通过另一个 MCP Server（比如 Vercel 或 Cloudflare 的部署服务）直接把代码部署上线——一个对话就完成了从"想法"到"上线"的全过程。

**第四步：Hooks 自动化护栏**

AI 在写代码的过程中，hooks 在后台无声运行：

- **每次文件保存后**，hook 自动运行代码格式检查，确保代码整洁
- **每次 AI 准备回复前**，hook 扫描回复内容，检查是否包含了 API 密钥或敏感信息
- **在整个对话结束后**，hook 自动把这次产出的文件列表和版本信息记录到一个日志里，方便以后回溯

你不需要手动执行任何检查——hook 就是你的"自动化安全网"。

**第五步：Subagent 并行处理**

在搭建博客的过程中，有些任务是独立的：

- 任务 A：设计首页的视觉方案
- 任务 B：写博客的"关于我"页面文案
- 任务 C：生成网站 SEO 相关的元数据（标题、描述、关键词）

AI 不是一个接一个地做。它同时 spawn 三个 subagent——设计方案、写文案、做 SEO——它们并行跑，各自在自己的上下文里专注干活。完成后，结果汇总到主线程。

**最终效果：** 你作为用户，感觉只是在聊天。但你背后运转的是一个完整系统——Claude.md 设规则，Skill 装能力，MCP 连外部工具，Hooks 自动守护，Subagent 并行执行。五样东西各司其职，组合成一套不需要写代码的"软件生产流水线"。

---

## 用人话总结：你只需要记住这几个类比

| 概念 | 一句话类比 |
|------|-----------|
| **Claude.md** | 贴在墙上的"员工守则"，不用每天重申 |
| **Skill** | 预制菜说明书，加载即用 |
| **Hooks** | 自动驾驶的传感器——检测到障碍物自动刹车 |
| **MCP** | USB-C 转接头，一个口连万物 |
| **Subagent** | 主编的实习生团队，领活→干活→汇报→回收 |

再看一遍这个表，然后想想你日常工作中那些"重复描述规则、手动复制粘贴数据、一次只能做一件事"的环节——你应该大概知道，哪一个概念可以用来解决哪一类问题了。

**Vibe Coding 不是什么"给 AI 打字就出网站"的玩具。它是一种新的工作方式——你不是在"操作机器"，你是在"管理一支 AI 团队"。**

而这五个概念，就是这支团队的"人力资源体系"。
